# 总评修订 · 设计目的论与重构方向

> 起因：客户指出总评的批判重点错位——"九天"的正确处置不是让它合理化，而是追问它为什么存在。

## 一、批评框架修订：从"事实审计"到"目的论批评"

我在 A1 里开的药方是"补一段搜寻实况"——这是在**花成本维护一个零功能的设定**。错误在于把审稿做成了事实一致性审计，而编辑的第一问应该是：**这个设定为什么存在？它制造张力，还是深化主题？两者皆否——删掉，而不是修好。**

"九天"检验：没制造张力（搜寻过程未被叙述）；没深化主题（与 10:37、主角、全城避讳都不挂钩）；唯一功能是"让尸体被发现"，任何数字都能完成。**它是空转的设定，没有维护义务。** 正确的批评是"为什么是九天？"——答案是"不为什么"，于是删。

审稿两问顺序：①目的问（张力来源／主题深化／零功能）→ ②一致问（仅对前两者提问）。总评 A 级九条中凡"需大量补丁维护"的设定都应先过目的问。真正的病根是：**全书唯一被深化的时刻只有 10:37，其余设定没有挂靠到它上面。**

## 二、重构思路的设计分析（客户方案）

核心理念：设定只有两个合法身份——张力的来源，或主题的深化；两者皆不是的，是待删的冗余，不是待修的事实。

1. **三重同停的因果闭合**：一次意外，女孩卡进钟的夹层，大钟被卡停、腕表同时被夹坏——"为什么都停在 10:37"从巧合变成**同一个动作的两个后果**。表作为遗物传到女主手上，10:37 从神秘数字变成可触摸的物证。
2. **全城避讳 = 日常中的裂缝**："差五分、差十分，绕开 37"——主角以为是民俗，读者跟他一点点意识到这是集体创伤。张力放在生活里而非案件里，比"搜寻九天"高级一个量级，且与游戏"从日常误导中找真相"的机制同构。
3. **主角的信息差 = 叙事不可靠的心理学地基**：幼年离开、成年回来的外人，对钟楼早有猜测，潜意识反而和他作对。不可靠叙述的来源从"恶意隐瞒"换成"防御性回避"——正是策划文档"从错乱叙事中找真相"的正解。玩家不是在抓骗子，是在陪一个不敢知道的人慢慢知道。
4. **48 小时白月光 + 记忆重写**：第一天给钥匙、第二天她没再来、第三天被带到外地——记忆只有两天，其余九年全靠自我重写。与第十章循环机制同构：**记忆每重播一次，两天被拉长一点，九年后已变成半生**。"两天怎么够爱九年"从漏洞变成主题（他爱的她本来就是他自己写的，呼应第三章）。
5. **爆发时刻的错位引擎**：长得像她的人进来，问一块卡在 10:37 的表，表背刻着那个名字。他终于开口："你的名字是 XX？"她只肯定，无进一步表示；他自卑地解释为"她早就不记得我了"。——**一个动作，两层解释（她的调查者伪装／他的被遗忘叙事），两层都是真的**，玩家与主角共享误解直到末期。"榛／蓁"同音错字从主题升格为情节引擎：他听成"蓁蓁"，她报的是"榛榛"，两人在一个音上错开九年。

## 三、需要补的设计点（编辑职责）

1. **第一章悬念换轨**：表背名字若在第一天引爆，"表的悬念"让位于"身份的错位悬念"——两者不能并存，建议选后者（更高明），第一章收束改为：他夜里擦表看到名字的那一下，白月光被击穿。
2. **"她答'是'"的伦理张力要收口**：她报的"许榛榛"是真名（户口上的榛来自姐姐起的小名），她在利用他的误解而非说谎。第八章须让她认账："你问我的名字，我答了。是你自己听成了她。"——错字主题从"他写错"升级为"他听错"，形成"写错→听错→爱上错的人"三级递进。
3. **隐瞒动机落地**：意外之夜他给了钥匙、约了她——在小城语境里说出来等于毁死者清白并卷入自己，母亲第三天带走他即是封口。这直接服务"控制型家庭"设定，且让第七章电话"你去看塔了？"获得新重量：她怕的不是塔，是儿子说出那两天。
4. **"意外"与罪感的平衡**：叶蓁之死是意外，则主角之罪只在榛榛之死，但"白月光幻想"正是暴力的心理前史——他爱的一直是自己写的她，所以当真人（榛榛）要带走表和真相时，才有"把她按住"的冲动。第九章"看守"独白在新框架下更顺，无需改动。

## 四、总评清单处置变化

| 原条目 | 处置 |
| --- | --- |
| A1 九天搜寻 | **撤销补丁方案**，改为删除/替换"九天"，发现机制挂靠到"全城避讳+修塔人例行开塔" |
| A2 钥匙矛盾 | 维持，但修复方向改为"第一天给钥匙"的新设定，钥匙从疑点变成他的罪证 |
| A3 时间线 | 维持，按 48 小时+九年重写的结构整体重排 |
| A4 元层残留 | 维持 |
| A5 升学设定 | 降级为细节：状元之死才是"全城的伤痛"的核心，升学说法全书统一即可 |
| A6 表后盖物证 | 升格为第一引擎（名字引爆+同音错字） |
| A7 寻找史 | 维持 |
| A8/A9 | 维持（编辑事故/年代） |

**结论**：客户的重构思路不仅更有设计，而且是把全书从"需要维护的事实堆"改为"围绕单一时刻的目的系统"的范式转换。建议第三版以本方案为骨架重写。
